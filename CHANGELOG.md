# Changelog

Releases of Glessner, newest first. Each release has a version, held in `pyproject.toml`, and a git tag, `v<version>`. Every output carries a build identifier: the version plus the commit. Version 0.1.0 predates this repository, so it has no tag here.

## [0.3.0] - 2026-10-28

Opening a case with this build upgrades it to case format 4, which 0.2.0 can't open. A case whose journal is read-only stays at format 3. Try it on a copy of the case first.

This build runs Eric Zimmerman's 2026.10 tools. Before you run tools with it, repeat steps 3 and 4 of `setup.md`, which install those tools and the .NET 10 runtime that AmcacheParser, RBCmd, SQLECmd, and WxTCmd now need. Until you do, RBCmd, SQLECmd, and WxTCmd don't start on the .NET 9 runtime in the tools folder's `dotnet-9` folder.

### Finding your way

- The Tools page names the rule or map set each tool's latest runs used, and both it and the Overview's **What the case holds** say how many rows a parser skipped. A Hayabusa lead's chips name the rule sets of the runs that made its hits.
- A reason that ends in a period no longer shows two, and the job box says why a load of found output left out every row.
- The timeline draws what you last asked for. Lanes for an earlier filter or Lanes preset that answer last are dropped, and a redraw asked for while the window moves draws the window the motion ends on. An offset, Align, a split, or its undo reads the case's range and Fit case's range again. The Sources boxes wait, disabled and showing an ellipsis, for the counts of the filter in force, and a split registers that filter again. A failed timeline reload says so. A logon link whose source host has no lane is counted in the hover of the window's event count, and the status line names those hosts, up to three and how many more.
- After the first run or import in a new case, the timeline opens on the case's events. It used to come back to the empty case's window, 1969-12-31 to 1970-01-01 UTC with no events in it, until you pressed **Fit case**. A reload now puts a saved window back only where it shows part of the span from the case's first event to its last.
- The Details panel keeps the page you asked for. A mark, a tag, a host change, an undo or retraction on the Audit trail, or a redraw of the Tools page or the Case overview's list that answers after you opened another page no longer draws over it. A page you left and opened again before the answer draws with the change. A redraw waits while a question, such as a second group's Accept all, is open on the page, and runs once the question has left. The trail band marks a step at once.
- A bidi control in evidence text, such as the right-to-left override that makes `report<U+202E>fdp.scr` read as a PDF, shows on the pages as a visible `[U+202E]`: in lists, on the Event page and its pivots, in the timeline's lanes and hovers, in the Sources panel, on the status line, and in the Start page's folder checks. A click that copies a value, Copy as JSON, the search box, and the View keep the character as recorded. Text you select on the page and copy holds the visible `[U+202E]`. A list's find box and the Sources panel's find box take `[U+202E]`.
- **Browse** on the start page opens only folders on this computer, and with no path it lists this computer's own drives. It refuses a UNC path, a path on a mapped network drive, and a device path through UNC or GLOBALROOT, such as `\\?\Global\UNC\server\share`, with "Browse doesn't open network folders. Type the folder's path instead." It refuses a device path on this computer, such as `\\?\C:\Windows`, `\\.\PhysicalDrive0`, a volume GUID path, or `\\?\Global\C:\Windows`, with "Browse doesn't open device paths. Type the folder's path instead." It refuses a path through a symbolic link or a junction, either of which can lead to a share, with "Browse doesn't open folders through a link. Type the folder's path instead." A refused path opens nothing, and Browse lists no symbolic link or junction as a folder. A cloud-sync folder such as OneDrive is still listed and opened, and a path you type into the start page's folder fields is still checked and opened, a share included.
- A host's name, address, role, OS, and time zone are read from its registry whatever the letter case of their key path, so a SYSTEM hive that writes `services` in lower case now gives its host its address, and Same service name finds a Sysmon registry event (12 to 14) under such a key. The host's time zone name is read up to its terminating null, so RECmd's trailing bytes, as in "Eastern Standard Time ard Time", no longer leave the host on a fixed offset with no daylight saving time. The Hosts panel adds a dotted name such as `dc1.ad` as a name, and takes a value as an IP only when it is four dotted numbers or holds a colon.
- A host whose IP has network logons (4624 type 3) that record another machine's workstation name, as after a stale DHCP lease, needs review, with a note such as "3 logons from 192.168.1.23 name ATTACKER-PC, not this host". The logon links stay as they are.
- A network or remote desktop logon (4624 type 3 or 10) whose source address, IPv4 or IPv6, is loopback, link-local, or unspecified, and that no collected host owns, now links by the workstation name it records, as a logon with no address does. A logon from any other address, private ranges included, never falls back to the name.
- The Overview's **What the case holds** takes each host's first and last time from its events dated 1990-01-01 UTC or later and no more than a day after the newest run, by the run's finish or, when it has none, its start. One event dated 3320, or a 1980 file time among 2024 activity, no longer stretches the span. A note under the span counts the events outside it with their dates, such as "1 event dated 3320-11-16, outside the rest" or "12 events outside the rest, dated 1601-01-01 to 3320-11-16". Those events still count in the host's events and show on the timeline. A host with no event in that range shows the span of all its events, with no note. Autoruns' PE link times set no span and count as no event outside it, unless a host holds nothing else. A case with no run has no upper bound.
- The tag picker's ATT&CK hint has a fixed width, so the menu keeps its width and stays 4 px inside the window. The Overview's last action spans both stat columns. When another listed case on the start page has the same name, the status line after **Remove from list** names the case's folder too.

### The Event page and pivots

- An $MFT event's message shows MFTECmd's SI<FN mark as `SI<FN`, without the words "possible timestomping", since MFTECmd sets that mark on most records of an ordinary volume.
- Zeek logs that join field names with an underscore, such as `id_orig_h` and `certificate_subject`, load with their addresses and ports in the event's fields and message, so `addr:` and the address pivots find them. A JSON log whose first record carries `ts` and `id_orig_h` is known as Zeek output whatever its file name. An x509 record's message shows its `certificate_subject`, and a pe record's message names its sections: as a JSON list from a JSON log, and comma-separated from a tab-separated log.
- A rebuild (`uv run glessner rebuild CASE`) writes the new $MFT flag words. Event IDs don't change, so marks, tags, and links stay on their events. A Zeek log loaded by an earlier build, from the Tools page or by an import, keeps the mapping it was loaded with when the case is rebuilt. To read its underscore names and pe sections, stop the server and import it again with `uv run glessner import CASE FILE --mapping zeek`, which replaces its events and keeps their IDs. Its records can then gain addresses, so a host's clock check can change: the check can pair them with that host's events, and a host whose check had no pairs can get a suggestion.
- A time the host's clock didn't write, such as an Autoruns PE link time, shows a **Host offset +N s** chip when its host has a clock offset, with the recorded time in its hover, and no clock note or host local time.
- On the Event page, the chip that names a host's clock offset, such as **Aligned -3599.5 s**, **Clock adjusted +N s**, or **Host offset +N s**, starts the header's second row, under the time it explains, instead of sitting in the first row. Its hover and keyboard focus are as before. The header's note box is 120 px wide, not 180. At 1,280 by 720 a 4624's kind on a short host name such as DC01, "4624 Successful logon, Security", is drawn whole, and with Hayabusa's suggested tags open it gets 174 px or more instead of vanishing, ending in an ellipsis when it is cut.
- RECmd's Services rows no longer start their message with "Services: None = ". A case an earlier build loaded keeps the old text until `uv run glessner rebuild CASE`. Event IDs don't change.
- The Event page says where to look when a pivot doesn't fit the event. Same file isn't offered for a 4656 or 4663 on an object that isn't a file, or for a 4660, which names no object. A 4660's reason points to the 4656 or 4663 from the same process with the same handle ID. Sysmon 3, 7, 8, 10, and 11 events and a System 104, which record no logon ID, say where the logon is: on the Sysmon 1 event that started the process or the source process, or, for a 104, on the Security log's 1102 when that log was cleared too. A Suricata or Zeek http record says where a download's file name and hash are, and a fileinfo or files record keeps its Same hash and Same file name rows.
- The Event page's badge and first decision take the most severe pending suggestion, Malicious, then Suspicious, then Authorized, as the lists do. A value named like a built-in property, such as `constructor` or `__proto__` in an artifact or LogonType field, or a lane named so, reads as written. A tag from a pivot list draws the list again, also when the ticked rows include the event on the Event page. An Event page left and opened again during a host change shows the new time. After a reload, **New finding** names its event again.
- Same source IP and port refuses a time window outside 1 to 3,600 s, the same range that Same host within takes.

### Marking, findings, and the report

- The report's Method table has a Rules column and lists the files each tool ran with, by SHA-256, and the report gives an event of found output the same evidence hash as its Event page. A run record that isn't a JSON object or lacks a key fails the report with a message that names its file.
- The report's Method table has a Tool check column after Rules. A run's cell gives its recorded tool check as **Matches pin**, **Differs from pin**, **Not pinned**, **Pins unreadable**, or **No manifest**, any other result word as written, and **Unknown** for a check with no result. A run with no tool check, such as an import, a load of found output, or a run in a case at format 3, has an empty cell. When any run record says its tool's files differed from the pin, the report's Evidence and integrity and the Case overview's Integrity each add one line that counts those runs and names their tools. A later run that matched doesn't remove an earlier one from the count, and a run that a later run replaced, or that failed or was stopped, is counted even where the Method table and the Tools page no longer show it. A run's record names up to 20 of the paths that differed.
- The timeline export gives Suricata's flow ID and Zeek's uid their own columns, `network.flow_id` and `zeek.uid`, right after `network.community_id`. `network.community_id` holds only a community ID, so a search on it across tools no longer matches a sensor's own flow number.
- An indicator that is a file in the Windows folder's own files, or below System32, SysWOW64, or Sysnative, stays in the report's table and `indicators.csv` with a note that it may be a system tool the attacker used, so check before you block it. The table gains a Note column, and the CSV a `note` column.
- **To investigate** lists the marked events 200 at a time, with a button that shows the next 200. When the marked events change before you click it, such as by a mark, a clock offset, or a split, the list is read again from the start, and the status line says so. A double click on the button adds the next rows once.
- The report's **Preview** lists the first 1,000 marked events and says how many there are in all. **Write report (Markdown)** lists them all.
- Writing the report re-hashes the evidence without holding up the case, so a mark made during the re-hash goes through at once, and the report lists it. If the manifest changes during the re-hash, the report re-hashes again.
- A reload (F5) on the Findings page brings back each open finding form, new or edit, with its title, severity, narrative, and ATT&CK picks, each retire reason being typed, and the report Summary's unsaved text. A save or other write on the Findings page keeps the other open forms, the retire reasons, and the Summary's unsaved text. An edit form whose finding changed since the form opened, such as in another tab, shows the finding's current value in each field you left alone, keeps your words in a field you edited, and names the changed fields, and **Save changes** sends only the fields you changed. When an edit form's finding was retired meanwhile, the status line says its changes are not kept. **New finding** from an Event page opens a kept new finding's form with its words, for that page's events.
- A double click on Add the finding journals one finding, not two.
- A mark, a suggestion decision, a host change, a clock alignment, or a rule write that the server accepted no longer reads as failed when the timeline then fails to reload. The status line says the write was made and the timeline didn't reload, so a retry doesn't journal it twice.
- A mark, a tag, a follow-up, or a tag suggestion decision that names an event twice journals it once and leaves one mark, or one row per tag, and a mark, tag, or follow-up counts it once in its answer, so the audit trail no longer counts the event twice. The count a confirm stated stays as the page sent it.
- Rejecting and restoring suggestions take the same limit as a mark, 200,000 events. Accept all and Reject all over that limit are refused in the row before anything is sent.
- A suggestion rule's number that reads as infinity or not a number is refused, and a rule journaled with one no longer stops the case from opening.
- The mark note box in a list reads "Note (optional)", as the Event page's does, and its hover says how many events the note goes with.
- The report's Summary is escaped for Markdown line by line, so it reads as typed. A path such as `\\10.20.30.50\evidence_share` keeps both leading backslashes. A line that starts with `- `, `+ `, `1. `, or `1) `, holds only dashes (with or without spaces among them) or equals signs, or is indented stays text instead of becoming a list, a heading, a rule, or a code block. The report drops the indent. The Summary keeps its paragraphs. In the file, each line that another line of its paragraph follows ends in a backslash, which a Markdown viewer draws as a line break. A finding's narrative gets the same line-start escape. Markdown typed in the Summary, such as bold text or a link, now prints as typed.
- A finding's events in the report are listed in order of their shown time, with events at one time by ID, an event without a time after the timed ones, and an event no longer loaded last. The list is cut at 25 after the sort. Before, the report listed the first 25 events linked, in the order they were linked.
- The report's Hosts table gives the Clock offset column as the offset applied (`none` or an offset such as `+5 s`), a semicolon, and what the clock check found: `not measured`, `matches the capture`, `aligned to the capture`, `pairs with the capture disagree`, `the reference clock`, or the seconds suggested and not applied. Before, a host with no suggestion read as a bare `none` or `+5 s` whatever the check found, so a host the check had no pairs for read like one that matched. It now reads `none; not measured` or `+5 s; not measured`.
- A bidi control in evidence text shows as a visible `[U+202E]` in the Markdown report, the report's Preview on the Findings page, the audit trail's Markdown, and the case state under the case name and its hover. `indicators.csv` and the timeline CSV and JSONL keep the character as recorded. The report and the audit trail also print a named character reference in evidence text, such as `&lt;` or `&rlm;`, as written. A Markdown viewer had drawn the character the reference names.

### Case records

- Case format 4: the upgrade from format 3 adds one entry to the journal and raises the number in `case.yaml`. The case's events, runs, and manifest don't change, except for found output that an earlier build loaded under a linked evidence path (the next bullet). A case from 0.1.0 goes through every step in one open, and a copy of a case from an earlier format takes the step to format 4 after the copy's own `case_created` entry. A format 3 case whose journal has no chain or has a break stays at format 3, the upgrade writes nothing, and the case opens read-only, as it did. `close` leaves a format 3 case at format 3, so it works beside a running server.
- Case format 4: the upgrade gives the event IDs a rebuild gives to found output that an earlier build loaded while `case.yaml` named the evidence through a link, such as a junction, a substituted drive, or a mapped drive. Those events named each file by its whole `//?/` path, and this build names it by its path under the evidence folder. For each such run, the upgrade reads the run's output once, keeps the names its events carried in a file in the case folder, loads the run again, which writes the run's record again with the new load's counts, and records each old ID the journal names with its new one in one rekey, so marks, tags, notes, and findings follow. It checks the journal first, so a case whose journal has a break stays at format 3 with its events as they were. A stop partway through leaves format 3, and the next open finishes the upgrade with the same IDs, unless the file doesn't fit the case or a run it names can't be read, which holds the case at format 3 with a message that says what to do. A run whose output changed since its load, or can't be read at the first open, keeps its rows and IDs, and the entry names it. A load of found output also replaces rows that name one of its files by its `//?/` path, matched to the files the earlier run read under the run's one root, so a file of the same name in another folder keeps its rows, also in a single-host case, and Add new evidence doesn't leave a file's events twice. A case with no such rows keeps every ID and gets the usual entry.
- Where the upgrade to format 2 found that an ID in the journal named more than one event, it left the journal's entries as written, and the Event page of each event the ID may have meant says so. When the upgrade to format 4 gives such an event a new ID, its Event page still says so. The format 4 entry counts only the IDs that journal entries name, so such events don't add to its count of journal references that now name new IDs, or to its count of events that hold references made under more than one earlier ID.
- The journal's `case_created` entry names the case's format, and a rekey of event IDs from format 3 to 4 counts only in the upgrade's own place: not in a case created at format 4, not after a manifest record, and not after another upgrade from 3 to 4. A hand-made one anywhere else is a break to the app and to `scripts/check_journal.py`, which checks a journal of case format 3 or later.
- Case format 4: each tool run records the rule or map set it used, as the run starts, for Hayabusa, EvtxECmd, RECmd, SQLECmd, and Suricata, such as `Hayabusa rules fffbdd1, files 7c30c465`, `Maps, 456 maps`, `DFIRBatch.reb 2.22`, and `ET Open 11310`. A Hayabusa rules folder that is a Git checkout is named by its commit and the first 8 hex digits of the folder's SHA-256, so an edited checkout reads differently from an unedited one at the same commit. One that isn't a checkout is named by the 8 digits alone. A run also records the SHA-256 of the tool's files: the executable, each `.dll` beside it, the executable's `runtimeconfig.json` and `deps.json`, each file its command line names in the tool's folder, the rule set's version file, and the folders the tool reads without an argument naming them. Those folders are Hayabusa's `rules` and `config`, the `Maps` of EvtxECmd and SQLECmd, SQLECmd's `runtimes`, which holds the native SQLite library its 2026.10 build loads, and RECmd's `Plugins`. A folder's hash covers every file in it and below, leaving out `.git` and links, and the Tool files row of `glossary.md` shows how to reproduce it with `sha256sum` in Git Bash. A link in such a folder is named in the run's notes. A tool file the run can't read refuses the run before anything is made, and the refusal names the file. A run made before format 4 has no tool hashes. The Tools page and the report show the rule or map set of a Hayabusa, EvtxECmd, RECmd, or SQLECmd run made before format 4 as not recorded, a Hayabusa lead's chip reads "Hayabusa rules not recorded" for such a run, and a Suricata run still shows its ET Open version. A case kept at format 3 records no rule or map set and no tool hashes, apart from Suricata's rule set version.
- A tools manifest, `tools_manifest.json` at the top of the tools folder, holds your pins: the SHA-256 of each tool's files, the same files a run records. From case format 4, each run compares its tool's files with the pin before it starts writing and records `matches`, `differs`, `not pinned`, `no manifest`, or `unreadable` in its run record, with up to 20 of the paths that differ. A run whose files differ still runs, and the Tools page, the job's step line, and `glessner run` say so. Pin with `glessner tools CASE --pin` or on the Tools page. Each asks first and names the manifest. The Tools page shows each tool's pin as **Matches pin**, **Differs from pin**, or **Not pinned**, among other states. A pinned tool has a **Pinned files** fold that lists its files. `glessner runs` has a check column.
- Suricata EVE lines that are cut short, aren't JSON, or are nested too deep to read, and MFTECmd rows with no readable time, make no event, and the run's notes count them: Suricata's for each file by name, and MFTECmd's in one note for the load. A rebuild replaces these notes rather than adding more. From case format 4, a run's record also counts the rows or lines a parser read and made no event of, for MFTECmd, Suricata, and imports, and a rebuild fills the count for runs made before format 4.
- Case format 4: the journal records the SHA-256, size, and line count of `manifest.jsonl` at each intake and Add new evidence, and a case copy carries its source's record. When the source couldn't vouch for it, because its journal has a break, no head of it is recorded on this computer, or its first record came with Add new evidence, the copy's record says why, and `verify`, `close`, the report, the Case overview's Integrity, the case state under the case name, and the audit trail repeat the reason, the case state as soon as the copy opens. A break or a head not recorded here is a warning in Integrity and the case state, and none of the reasons changes the exit of `verify` or `close`. `verify`, `close`, and the report compare the file with its record and say whether it matches, grew past it, differs, or has no record. `verify` and `close` exit 1 when it grew past or differs from its record, and `verify` also exits 1 when it is missing while the journal records it.
- Add new evidence refuses a `manifest.jsonl` that differs from its record, and `intake` refuses to write a new manifest over a missing one that the journal records. The case state and the Overview's Integrity warn when the newest full re-hash found `manifest.jsonl` changed or missing, and never call such a re-hash matched.
- A case upgraded from format 3 gets its first manifest record at the next Add new evidence that adds a file, and that record vouches only from then on.
- A load of tool output found in the evidence replaces only rows that earlier loads of the same tool's found output put on the same host, never a tool run's or an import's. A row naming another host's file or a path outside the evidence replaces no rows of other loads, and a reload of the same files replaces the earlier load whole. Rows naming a file whose events the case holds from a run of the same tool on the host are left out, and the Case overview's gaps say so when that leaves a load empty. The Event page cites the intake hash of the output its run read, not of the file the event names. Event IDs don't change.
- The text of the entry that upgrades a case from format 1 to 2 now counts the journal's references that name no loaded event, such as a mark on an event no run gives, in one more sentence, for example "2 journal references name no loaded event." It says nothing when every reference names a loaded event, and nothing for a case with no events database.
- Intake, Add new evidence, and each later check record a cloud placeholder, such as a OneDrive file whose content isn't on the disk, as unreadable without opening it, since opening it would download the file. A tool that reads a whole host folder is refused while that folder holds one. An import preview, an import, a tool run, and the copy step of a tool that works on copies refuse a file that became a cloud placeholder after intake hashed it, and name it, instead of reading it and downloading it with no record. For such a file the refusal says to make it available on this disk and try again, since intake's hash still covers it. When a run of a tool that lists a host's folder is refused, the refusal tells these files apart from a placeholder that intake never hashed.
- A journal entry from before case format 3 whose `who` isn't text, such as a list, no longer makes the Case overview or the audit trail fail. The audit trail and its export, the Case overview's last action, and the report show such a `who` as its JSON text, such as `["ann", "lee"]`.
- The audit trail checks the journal's chain once and keeps that check between requests only while the journal, the head recorded outside the case, and the side files its entries name are as they were, so it still finds an edit that keeps an entry's length. A side file that was replaced, changed, or deleted shows on the next request, and a check made while the journal's last line was being written isn't kept. The audit trail's export reads the events of every entry that lists several in one query.
- `verify` exits 1 when the manifest lists no file, since nothing was checked, and `close`, the report, and the audit trail say that no evidence file was checked. It also exits 1 when intake hashed none of the manifest's files, and says no evidence file has an intake hash to check. A case where intake hashed some of its files exits as it did.
- A `run.json` that lacks a key, or isn't a JSON object, is refused with a message that names the file and each missing key. The Tools page and the Case overview show that message, and `glessner runs` prints it and exits 2, where before they failed with a TypeError. A rebuild that fails on a case whose events database holds no events records its runs as unfinished, with no rows loaded and a note.
- Making a new case or a copy at the path of a deleted case removes the journal head that this computer recorded for the old case, so the new case isn't checked against it. If that record can't be removed, the case isn't made: the refusal names the record's file, and the empty folders made for the case are removed.
- A process waiting to write the journal is no longer passed over by a writer that lets go of the lock and takes it again. Before, a command beside a busy server could keep missing the lock and fail after 10 s.

### Running the app

- The start link works once. The page trades the link's token for a session, which the browser keeps for this server's address and port and the page sends in a request header, so other web servers on 127.0.0.1 don't receive it. The session cookie is gone. A used link opens nothing in a second browser, so `serve` says on its link line that the link works once, and `--no-browser` lets you open it in the browser you choose. Where the browser blocks site data, the session ends when the page reloads or moves between the start page and a case. An import and a Tools run that loads events reload the page, so they end it too, and getting back in then needs a new link from a server restart.
- `glessner serve CASE` says, for a case of an earlier format, that the open upgrades it to format 4. Once the case is open, it says whether the case is now at format 4, which older builds can't open, or its journal is read-only, so the case stays at format 3 and opens read-only.
- Stopping `glessner serve` with Ctrl+C waits up to 5 seconds for running requests, then interrupts any statement still running on the events database and closes it. A request in a long count no longer holds the stop up, and one that finishes within the wait answers instead of failing. If any requests were still running when the wait ended, the command says how many. A load or tool run started from the Tools page isn't a request and isn't waited for, but the rebuild of the case's tables that follows a load is, and is cut off the same way.
- Opening a case again from Cases waits up to 5 s for its earlier open to finish, and an open of another case meanwhile doesn't wait. If the wait runs out, the open is refused and the case stays open as it was. A case whose database connection failed to close can be opened again without a restart, and a reopen no longer waits for the earlier open's last answer to finish sending.
- `load-output`, `run`, `import`, and `verify` without `--journal` refuse a case that has no intake manifest yet, with exit code 2 and "No intake manifest yet; run intake first."

### Tools and their output

- Glessner moves to Eric Zimmerman's 2026.10 tools. AmcacheParser, RBCmd, SQLECmd, and WxTCmd are now the .NET 10 builds: they download from Eric's `net` folder and run on a .NET 10 runtime unpacked in the tools folder, in a `dotnet-10` folder. The other eight stay the .NET Framework 4 builds. Steps 3 and 4 of `setup.md` install them.
- Upgrading from 0.2.0: the .NET 9 builds of RBCmd, SQLECmd, and WxTCmd no longer start on the runtime in the `dotnet-9` folder, because Glessner now gives these tools only a .NET 10 runtime. Until you repeat steps 3 and 4 of `setup.md`, they show `unknown`. With no .NET 10 runtime in the tools folder, `glessner tools` adds `Can't run here`, as the Tools page does for a tool the case has evidence for, and a run of one is refused. With one, a run starts and fails with the .NET host's exit code. A .NET 9 runtime installed machine-wide still runs them while the tools folder holds no .NET 10 runtime. AmcacheParser's .NET Framework build keeps running until step 3 replaces it with the .NET 10 build. The `dotnet-9` folder can then be deleted. A pin made for an earlier build shows `differs`, so pin the new builds again.
- A tool that needs a .NET runtime the tools folder doesn't hold, and whose version check ends with the .NET host's own error, shows `Can't run here` with the runtime it needs in `glessner tools`, and on the Tools page when the case has evidence for it. The Tools page's version cell names the runtime to unpack either way. A run of it is refused with the same words. Before, the run started and failed with the host's exit code. A check that ends any other way, such as by timing out, marks nothing. `glessner run --all` names each such tool as left out, loads what else is ready, and exits 1. The Tools page's **Run and load everything ready** leaves such a tool out, and its row says why. Output of such a tool found in the evidence counts as ready to load, as Suricata's does without Npcap. `glessner tools` now also gives the reason for Suricata without Npcap, and `run --all` names it the same way, where before it left it out without a word.
- SBECmd 2026.10 writes `<yyyyMMddHHmmss>_SBECmd_<version>_ConsoleLog.txt` where earlier builds wrote `!SBECmd_Messages.txt`. Glessner reads each CSV's hive from either, in its own runs and in SBECmd output found in the evidence, and a run must leave one of the two. A load of SBECmd output found in the evidence checks the messages file or console log beside its CSVs along with the CSVs, and one that changed, went missing, or isn't in the manifest fails the load. A rebuild leaves such a load out when that file changed or went missing. When the manifest doesn't list it, the rebuild reads it unchecked and says so in the run's notes, and Add new evidence lists it so the next rebuild checks it. The console log that every 2026.10 tool writes is hashed with a run's output, but it is none of the tool's own files, no pin holds it, and no other parser reads it. Intake lists these logs among the unidentified files, each with the note "an Eric Zimmerman tool's console log; no events are loaded from it".
- EvtxECmd 2026.10 writes each value as the event's own text, where earlier builds left XML entities such as `&amp;` in it, and ends its CSV with a `RenderingInfo` column. Glessner unescapes only rows without that column, so a scheduled task's XML that holds its own `&amp;` still parses.
- Running the 2026.10 tools again changes some results. MFTECmd, given a `$J` and its `$MFT`, resolves folders that 2026.5.0 left as `.\PathUnknown\Directory with ID ...`, and also writes a copy of the `$MFT` CSV, tens of megabytes, into the run's output, which Glessner hashes and doesn't load. RECmd keeps rows from hives where 2026.5.0 stopped on an error. EvtxECmd's 4624 messages name the authentication package as the tool's map writes it, `AuthenticationPackageName: NTLM`, and Glessner leaves out its own `AuthenticationPackage: NTLM`, which messages from earlier builds and 4625 messages keep. Its 4688 messages give the process ID and the parent's in the right order. Event details gain fields the new builds add, such as AmcacheParser's Publisher, WxTCmd's AppActivityId, and RBCmd's Removed. PECmd's new FullPath column and LECmd's four new Droid columns, such as FileDroid, don't reach the event details. A case loaded with earlier builds keeps its events until the tools run again.
- A date and time that Windows wrote for the reader's locale, with a left-to-right mark before each part, loads without the marks when its field's name contains `Date` or `Time`, as Task Scheduler event 800's `LastRunDateTime` does, or when it is the unnamed data of CAPI2's 4111 to 4113, or of event 6008 (an unexpected shutdown) as the built-in XML reader reads it. A message part that repeats such a value loses the same marks, so a search for the date as shown finds it. Such a mark anywhere else stays, in a name shaped like a date too, and the pages show it as `[U+200E]` or `[U+200F]`. A case loaded earlier keeps the marks until `uv run glessner rebuild CASE`.
- LECmd, PECmd, EvtxECmd, and Hayabusa read only files named `*.lnk`, `*.pf`, or `*.evtx` in a folder, while intake identifies a file by its content. A run of one of them notes each file that intake identified for the tool but that is named otherwise, which the tool never opens, and a run on a host whose every such file is named otherwise is refused. Before, such a file was listed as an input of the run with no note, and its events, and Hayabusa's alerts on an event log, were missing.
- SBECmd replays the transaction logs collected beside each hive, so it reads the newest ShellBags. It runs with `--nl`, which skips the logs of every hive, only when a planned hive has no log beside it, and the run's notes then name those hives.
- A run still recorded as running, such as after Ctrl+C, a closed window, or a crash, is marked failed as interrupted when the case is next opened for work. `run`, `load-output`, and `import` do the same before they start, and say which runs they marked.
- The Import page keeps the mapping you chose through Add new evidence and when you open the page again. A change to the mapping starts from the one last asked for, so a change made before the last preview answers keeps it.
- `import` finds a file given by its absolute path where `case.yaml` names the evidence folder through a junction or in extended-length form. A path outside the evidence folder is still refused.
- An import is refused while a Tools job runs, before any file is read.
- An event too large for one row no longer fails its whole load. Before, a row over about 20 MB failed it. Now a row over about 16 MB has its longest text fields cut to fit, each ending in a note of how much text it had. When its extra fields can't be cut to fit, they are left out, and the message says so. The fields that identify the event, its time, and its lane are never cut.
- The built-in event XML reader reads a file name that holds an unpaired UTF-16 surrogate, which Windows allows, and writes that character as U+FFFD. It writes its progress and errors as UTF-8, so a file whose path holds characters the Windows code page can't write, such as a Japanese file name on an English system, no longer fails the run. A run that can't write its list of input files records why and doesn't start the tool.
- A Tools step that covers several runs shows their most serious evidence check. It reads "not checked" when a run was refused before it read anything, and "not read" for a load that failed while it read, where it read "ok" before.
- `scripts/suricata_rules.py` refuses an ET Open set without `classification.config` before it writes anything. It replaces `suricata.rules` last, so a build that fails partway leaves the earlier rules in force and removes its temporary files.

A legend of every mark the timeline draws opens with **Legend** or L.

### The Event page and pivots

- The Event page ranks the next pivots for the kind of event it shows, from a fixed table with its sources. Each row gives its reason and how many events it finds across the case before you click, and flags broad ones, such as a pivot on a system session or a shared Windows program. A pivot the event can't take is named on one line with the reason.
- Every source a caveat or a pivot shows is a public page or a file in the repository.
- A trail above the page keeps the pivots you took and the events you opened from them, and **Save trail as a note** journals it on the event the trail started from.
- One line under the header says which tool and run read the event, from which evidence file and record, whether the file's hash still matches intake, and the build. A caveat says what that kind of record does not prove, such as a Prefetch file showing that a program ran but not who ran it.
- The logon caveat says that on an NTLM logon the workstation name is the one the client sent, and cites Microsoft's MS-NLMP specification. The Amcache caveat cites Valhuntir's SRUM page for SRUM as a sign that a program ran.

Same file name matches the file's name alone, in any folder and without letter case, bare names such as SRUM's included, and its hover warns that it joins every file of that name. Same account matches an account however it was written, such as `C137\Administrator` and `Administrator@C137.LOCAL`.
- The right-click menu's Find related lists the pivots the Event page offers for the event, in the kind's order and without counts.

### Marking, findings, and the report

- **To investigate** is a worklist with progress. Each Malicious or Suspicious event has a **Followed up** tick you set, and beside it what is still unreviewed around it, as counts that open each pivot's list. Pending suggestions are grouped by rule, each saying why it fired, with **Review one by one** (A accepts, R rejects, N moves on), **Accept all**, and **Reject all**.
- A group action asks first. Accept all, Reject all, and a mark or tag of more than 25 hand-picked events name what they cover and the count the page loaded, and act only on those events.
- **Findings** are conclusions you write: a title, a severity in words, a narrative, ATT&CK techniques, and the events that support them. Each finding shows what its events do not prove. The app never writes a finding or its words.
- The Markdown report replaces the findings summary. Its seven sections are Summary, Findings, Timeline of marked events, Indicators, Hosts and clocks, Evidence and integrity, and Method.
- Each export says its scope and contents before you click. Marked-event exports cover the whole case whatever the window. The new **Indicators** export lists the addresses, domains, hashes, accounts, file paths, services, and tasks parsed from the events marked Malicious. Network rows carry ECS columns: the signature as `rule.name` with `rule.id` and `event.severity`, the record type as `event.dataset`, and `network.community_id`, `url.full`, `dns.question.name`, `tls.server.name`, and `client.mac`.
- Every file the case writes is hashed and journaled, and **Written from this case** lists each with its rows and SHA-256.
- A finding's ATT&CK field is a pick list: typing an ID or words of a name lists Enterprise ATT&CK v20.0's matching techniques and sub-techniques, and only a listed one can be picked; the server refuses any other. A finding saved earlier keeps its IDs, and one that isn't listed shows flagged, such as "T1086 (revoked; now T1059.001)", and must be removed before the techniques can be edited. The list ships with the app, with MITRE's copyright line and license.
- The tag picker's technique box is the same pick list, one technique at a time, and the server tags only a listed technique: a revoked ID is refused with its replacement named, such as "T1086 is revoked in ATT&CK v20.0; it's now T1059.001." An event's older tag on an ID off the list is kept, shows flagged on its chip, in the View panel, and in the report, and can be removed. Hayabusa's suggestion of a revoked ID is made as its replacement, and of an ID off the list not at all.
- The Findings page's Report and Exports sections each open under a band heading.
- No cell of a CSV the app writes can run as a spreadsheet formula. This covers the timeline CSV of every scope and `indicators.csv`. A text cell that begins with `=`, `+`, `-`, `@`, their full-width forms, a tab, a carriage return, or a line feed gets a tab in front. So does such an operator after a semicolon or a line break inside the cell, with or without one double quote between. The header row is fixed app text and goes out as written, `@timestamp` included. Every text cell is quoted, and Excel and LibreOffice keep these cells as text.
- The Exports cards name their network columns, say that a tab goes in front of text a spreadsheet would run as a formula, and say that JSONL keeps values as written.
